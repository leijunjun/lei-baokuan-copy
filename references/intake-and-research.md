# 产品采集、确认与研究

## 采集方式

先读取已有信息，再按缺口提问。首轮建议用以下三组问题，用户可一次提交资料，也可逐组回答：

1. “请提供要复刻的原视频或链接。你的商品叫什么、属于什么品类？请附正反面包装图或现有商品图；有多个 SKU 时指出本次主推款。”
2. “这款商品的规格、主要卖点和使用场景是什么？你认为谁会购买、为什么购买？不确定的可以先留空，我会研究后给你选。”
3. “本次实际售价、促销政策和赠品是什么？请说明活动时间、购买门槛、数量、适用 SKU/地区等条件；没有活动或赠品请直接写‘无’。”

仅在影响创作时追问：演示素材/细节图、能证明卖点的资料、人物或场景要求、禁用说法、必须出现的品牌文字。时长、画幅、字幕、分段和指定模型可先采集，统一在方向确认时收口。

涉及真实交易信息，用户资料拥有事实优先级。公开页面中的旧价、券价或其他店铺赠品不能替代本次促销确认。促销尚未确定时可在用户确认后采用不含具体优惠的方案，不在可复制成稿留下“XX 元”等占位符。

## 产品信息确认卡

| 字段 | 汇总内容 | 来源与状态 |
| --- | --- | --- |
| 产品名称/品牌/SKU | 本次准确名称和主推款 | 用户文字 / 图片可读部分 / 待确认 |
| 包装与外观 | 形状、主色、标签、规格，素材编号及路径 | 实际看到的图片；不可读小字不猜 |
| 卖点与证据 | 逐条列出，区分参数、主观感受、效果声明 | 用户确认 / 资料支持 / 未核实 |
| 需求与人群 | 已有定位；没有则注明待研究 | 用户自述或暂缺 |
| 价格促销 | 售价、优惠方式、时限和门槛 | 本次活动信息 |
| 赠品 | 名称、数量、领取和库存条件；或无/未知 | 用户提供 |
| 素材与限制 | 商品图/演示视频编号、不能出现的表达 | 用户要求 |

询问：“以上产品资料是否准确？请确认，或指出需要修改的项。”已知资料不足以支撑关键卖点时一起点明。确认未知项意味着保留为未知，不能将其变成可使用的事实。

## 需求与人群研究

触发条件是产品资料中需求或人群缺失。商品参数丰富也不代表购买动机明确。优先研究真实购买者为什么买、什么时候用、担心什么、与什么方案比较，避免只找品牌宣传口号。

按以下顺序进行有边界的搜索，找到足以区分两个方向的证据即收敛：

1. 同款：用“品牌 + 名称 + SKU/规格 + 评价/问答/使用场景/为什么买”等组合，检查电商公开评论/问答、公开使用体验及品牌资料。首先匹配商品身份，防止同名不同款。
2. 同款证据不可得或不足时，改用“品类 + 购买原因/使用场景/评价/困扰”等查询，参考同类真实体验及品类信息。
3. 记录能访问的来源页面、日期和简短证据摘要，按“同款证据 / 品类线索 / 创意推演”标注。对用户自述另列“用户提供”。引用用真实可打开的原始页面链接，不编造评论、销量、比例或评论者身份。

如果只能访问搜索摘要，标为摘要线索，不能声称已读完评论或视频。需要登录而无可用访问能力时，不绕过访问限制；报告缺口，使用可访问材料。搜索失败仍可以结合已确认产品给出两个假设，但必须说明这两组是待用户确认的推演。用户要求不联网时遵循其要求，并标明未进行公开研究。

同类线索支持的是“可能有这种动机”，不是“本产品具备这种效果”。未经证实的健康、收益、性能等声明不能进入目标商品的确定性台词；改用可验证的物理展示、已确认参数或主观体验角度。

## 两组方向选择卡

每个方向都绑定需求和人群，避免输出两个只有措辞不同的选项。不要无依据地凭年龄或性别定人群。

| 选项 | 用户为什么需要 | 谁在什么场景需要 | 依据与不确定性 | 怎样迁移原片 |
| --- | --- | --- | --- | --- |
| A | 从已确认资料/研究提炼一个购买动机 | 具体任务、场景、购买阶段 | 来源分类、摘要及链接 | 适用的开场、演示、情绪和收尾 |
| B | 与 A 有实质差异的购买动机 | 与之匹配的另一人群/场景 | 来源分类、摘要及链接 | 对应的另一创意切入点 |
| C 自定义 | 用户可以改写需求 | 用户可以指定人群，或混合 A/B | 用户选择 | 随选择调整 |

在卡片之后合并询问字幕、其他叠加文字、分段形式、时长/画幅和特殊要求。若目标人群与原片风格冲突，给出具体适配建议；不要为保持相似度忽略用户选择。
